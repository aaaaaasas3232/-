```
  ├── #2 当前 AI 人设

```

### 1.3 nook SDK 设计

**nook 是独立的设置 app**。新增 `window.nookSdk.prompts`:

```js
window.nookSdk.prompts.list()           // 返回所有 nook prompt
window.nookSdk.prompts.toggle(promptId) // 启停
window.nookSdk.prompts.reorder(ids)     // 重排
```

**数据结构**:
```js
{
  id: 'nook-persona-user',
  kind: 'persona',                    // persona | worldview | (未来 music/weather...)
  label: '当前用户人设',
  content: '...',
  active: true,
  order: -100,
  locked: false                       // persona 可编辑,worldview 可启停
}
```

**nook SDK 内部数据源**:
- `list()` 从 `settingsSdk.persona.user` + `settingsSdk.persona.activeAi` + `settingsSdk.worlds.getBoundFlows()` 拼装
- 用户状态存 `app.state.chat.systemPromptInject[aiPersonId][kind]`
- 顺序存 `app.state.chat.systemPromptOrder[aiPersonId]`

## 3. 概要系统 (v0.61.3) — 占位版

### 3.1 三种概要类型

| 类型 | 数据源 | 存储位置 | 生成入口 | 用户可控 |
|------|--------|---------|---------|---------|
| **日历概要** | chatArchive 选定的日期范围 | `aiPerson.socialProfiles.chat.calendarSummaries[]` | 历史消息页(日历模式) | 是 |
| **故事概要** | chatMessages 整个故事 | `aiPerson.socialProfiles.chat.storySummaries[]` | 历史消息页(故事模式) | 是 |
| **滚动 K 链** | 自动生成 | `aiPerson.socialProfiles.chat.rollingSummaries[]` (K0/K1/K2 链) | 后台自动 | **可选择开启/关闭** |

### 3.2 数据结构

**calendarSummaries**(选几天合并成一个概要):
```js
{
  id: 'cs-2026-08-08-001',
  title: '2026-08-07 ~ 2026-08-08 聊天概要',
  dateRange: { start: '2026-08-07', end: '2026-08-08' },
  messageCount: 23,
  content: 'AI 生成的概要文本...',
  generatedAt: 1723123456789,
  asPrompt: { active: true, order: 5, source: 'calendar-summary' }
}
```

**storySummaries**(一个故事一个概要):
```js
{
  id: 'ss-001',
  storyId: 'story-001',
  title: '故事概要 - 魔法学院篇',
  content: '...',
  generatedAt: 1723123456789,
  asPrompt: { active: true, order: 6, source: 'story-summary' }
}
```

**rollingSummaries**(K 链,自动压缩):
```js
{
  id: 'rs-001',
  level: 0,                          // K0 / K1 / K2 ...
  startMsgId: 'msg-100',
  endMsgId: 'msg-200',
  content: '...',
  threshold: 20,                     // C 窗口大小
  style: 'concise',                  // concise / detailed
  generatedAt: 1723123456789,
  asPrompt: { active: true, order: 99, source: 'rolling-summary' }
}
```

### 3.3 滚动摘要 K 链设计(★ 核心)

**K 链机制**(从 `chat迁移/聊天app迁移规划_314ca0f8.plan.md` §3.2):

```
C 窗口(最近 N 回合原始消息)   K 链(累积压缩摘要)
───────────────────        ──────────────
[回合1, 回合2, ..., 回合N]  [K0, K1, K2]
       │                     ↑
       │ 满 N 回合            │ 压缩合并
       ▼                     │
C 满了 → 压缩 ──────▶ 生成新 K ──▶ 追加到 K 链
                              │
                              ▼
                        K 链太长 (>M)
                              │
                              ▼
                        合并最早的 K
```

**用户配置**(`chat-settings` - AI 设置卡,2 个字段):
- `contextRounds: number` ← 上下文回合数(也是 C 窗口大小)
- `kMergeSize: number` ← K 链中每多少个回合合并成一个 K
- `rollingEnabled: boolean` ← **新增 toggle**(用户可开启/关闭滚动摘要)
- `rollingStyle: 'concise' | 'detailed'`

**自动触发时机**:
- 每次 chat-page 渲染时检查 C 窗口(回合数)
- 超过 `contextRounds` 回合 → 触发压缩(把最早的几个回合压成 K)
- 压缩时按 `kMergeSize` 个回合合并成一个 K
- v0.61 占位:压缩内容 = 前 N 个回合文本拼接 + `[滚动摘要占位 - 待 AI 接入]`

### 3.5 概要保存流程(完整版)

```
用户点「生成概要」
   ↓
弹窗选范围(选几天 / 选预设)
   ↓
占位 AI 生成概要内容(本版本:拼接消息文本)
   ↓
弹出「保存概要」弹窗:
  - 标题输入框(可编辑)
  - 概要内容 textarea(可编辑)
  - [重 Roll] 按钮(保留原概要,弹新弹窗输入不满意点)

  - [保存为独立 prompt] → asPrompt.active=true → 出现在 prompt-manager
  - [仅保存不进入 prompt] → asPrompt.active=false
```

### 3.6 上下文回合 prompt(★ 第三种 prompt)

**这是独立于概要系统的第三种 prompt**

**位置**:`chat-settings` → AI 设置 → 「上下文长度」(单位从「条」改成「回合」)

**触发逻辑**:
```
用户设置 20 回合
   ↓
chat-page 渲染时实时计算:
  - 从最新消息往前数 20 个回合
  - 1 回合 = 用户发 1 条 + AI 回复 ≥1 条(成对才算 1 回合)
   ↓
拼成文本:[当前聊天回合]\n用户:xxx\nAI:yyy\n...
   ↓
作为动态 prompt 出现在「当前上下文」section
   ↓
每次新消息后,该 prompt 内容实时更新
```

**长按发送按钮机制**:
- 用户连续发多条消息(不发 AI)
- 长按「发送」按钮一次性发给 AI(类似微信的"全部发送"功能)
- AI 读取后返回 N 条消息
- **这 2 组消息 = 1 个回合**(用户组 + AI 组)

**示例**:
- 用户发 5 条(长按发送) → AI 回 3 条 → **1 个回合**
- 用户发 1 条 → AI 回 2 条 → **1 个回合**
- 用户发 2 条 + AI 回 4 条 + 用户发 1 条 + AI 回 1 条 → 2 个回合(2 组)

**数据**:
- 用户设置:`app.state.chat.contextRounds[aiPersonId] = number`
- 回合数据:**实时计算**(不存 IndexedDB,每次渲染前算)
- 计算方式:按「长按发送按钮」分组,每组(用户组 + AI 组) = 1 回合

## 5. SDK 注册接口 (v0.61.5)

### 5.1 目标

其他 app(如音乐 app)注册 prompt:
- 自动出现在 prompt-manager「可用 Prompt」section
- 用户可启停/编辑/删除
- 不需要改 chat-app 代码

### 5.2 SDK API

```js
window.settingsSdk.appPrompts.register({
  appId: 'music',
  promptId: 'music-share-prompt',
  label: '分享音乐卡片',
  content: '当用户请求分享音乐时,使用 [分享音乐:歌名:歌手] 格式...',
  category: 'special-action',
  previewType: 'music-card',          // 'text' | 'music-card' | 'red-packet-card' | 'location-card'
  previewData: { song: '晴天', artist: '周杰伦', cover: '...' },
  defaultActive: true,
  defaultOrder: 10,
});

window.settingsSdk.appPrompts.unregister(appId, promptId)
window.settingsSdk.appPrompts.list()                // 所有注册 prompt
window.settingsSdk.appPrompts.listByApp(appId)      // 按 appId 过滤
window.settingsSdk.appPrompts.getState(appId, promptId)   // UI 状态
window.settingsSdk.appPrompts.setState(appId, promptId, state)
```

### 5.3 数据存储(混合方案)

**注册表**:`settingsSdk._appPromptRegistry` (内存 Map)
- 卸载 app → 内存清空
- 重装 app → app 启动时重新调 `register()`

**用户状态**:IndexedDB 新表 `appPromptStates`(永久持久化)
```js
{
  key: 'music::music-share-prompt',
  active: true,
  content: '...',           // 用户编辑后的内容
  order: 10,
  customPreviewData: null,
  updatedAt: 1723123456789
}
```

**卸载行为**:
- app 卸载 → 内存注册清空
- **用户状态保留**(用户编辑过的内容、启停状态)
- app 重新安装 → 重新 register → 自动读取 `appPromptStates` 恢复用户状态

### 5.4 chat-app 集成

`prompt-manager-page.js` 读 `settingsSdk.appPrompts.list()`:
- 「可用 Prompt」section 显示所有 appPrompt
- 每条带 `[音乐]` `[天气]` 等 app 标签
- 启停/编辑/删除联动 SDK

**特殊卡片预览**:
- `previewType: 'music-card'` → 展开显示真实音乐卡片
- 卡片下方有 `<textarea>` 显示卡片 div 样式代码
- 按钮组:`[保存] [编辑] [复原]`
- 无特殊卡片类型 → 不显示展开区域
