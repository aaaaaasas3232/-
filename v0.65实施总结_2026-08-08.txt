三、SDK 数据模型详解
================================================================================

【层级配置】
aiPerson.socialProfiles.chat.memoryConfig = {
  version: '1.0',
  levels: [
    { id: 'L1', name: '日概要', cycle: 1,   order: 1, editable: false, deletable: false },
    { id: 'L2', name: '周概要', cycle: 7,   order: 2, editable: true,  deletable: true  },
    { id: 'L3', name: '月概要', cycle: 30,  order: 3, editable: true,  deletable: true  },
    { id: 'L4', name: '年概要', cycle: 360, order: 4, editable: true,  deletable: true  },
  ]
}

【概要记录】
aiPerson.socialProfiles.chat.memorySummaries[] = [
  {
    id: 'ms-{ts}-{rand}',
    storageLevel: 'L1' | 'L2' | ...    // 存在哪层
    title: '8月1日 聊天概要',
    content: '...',
    sourceLevel: 'L0' | 'L1' | ...,    // 由哪层合并而来(L0=原始消息)
    sourceIds: ['ms-xxx', ...],        // 消耗的下层概要 id
    sourceDates: ['2026-08-01', ...],  // 涉及的日期
    cycle: 7,                          // 生成时的周期值
    consumed: false,                   // 是否被上层消耗(软标记)
    deleted: false,                    // 软删
    generatedAt: ts,
    messageCount: 12,
    originalDateRange: { start: '2026-08-01', end: '2026-08-07' },
    asPrompt: { active: true, order: 999, source: 'memory-summary' },
    createdAt: ts, updatedAt: ts,
  },
  ...
]

【硬约束】
- L4.cycle > L3.cycle > L2.cycle > L1.cycle
- 上层周期 > 下层周期(数组中 idx+1 = 下层)
- 所有 cycle >= 1
- L1 永远存在 + 永远是 order=1 + 永远 editable=false + deletable=false

【满 N 消 N 规则】
- L2 周概要: 当 L1 存量 ≥ 7 时可点「生成」
- L3 月概要: 当 L2 存量 ≥ 30 时可点「生成」
- L4 年概要: 当 L3 存量 ≥ 360 时可点「生成」
- 生成后: 消耗的 N 条下层标 consumed=true(不再被新生成看到)
          新增 1 条上层概要(默认 active=true)

【改周期后果】
- 校验新周期满足硬约束
- 通过后: 该层所有 consumed=true 的概要回退为 consumed=false
          下层概要数据完全不变(下一层概要本身依然存在)

【删层级后果】
- 软删该层所有概要(deleted=true, 数据保留可恢复)
- 该层 order 从数组移除,上层概要自动降级(order 重排)
- 上层概要里 storageLevel=L3 的字段不会因为「降级」而变成 storageLevel=L2
  sourceLevel 引用依然是 id,不是 order → 软删允许将来「恢复」

【加层级后果】
- id 自动生成 L5/L6...(默认 L1~L4 已存在)
- 临时加入列表 → 重新分配整型 order 1..N → 校验约束 → 通过后写回
- 该层初始存量为 0(没有任何概要)
- 已有概要的 sourceLevel 引用不变(因为增层不影响已有数据)

四、SDK 完整 API 列表
================================================================================

【配置层】
- getConfig(aiPersonId) → { version, levels }
- setLevels(aiPersonId, levels[]) → Promise<{ok, error?, levels?}>
- addLevel(aiPersonId, {name, cycle, position}) → Promise<{ok, error?, level?}>
- removeLevel(aiPersonId, levelId) → Promise<{ok, error?}>
- updateLevelCycle(aiPersonId, levelId, newCycle) → Promise<{ok, error?, clearedCount?}>
- validateCycleConstraints(levels[]) → {ok, error?}

【数据层】
- list(aiPersonId, levelId?) → Array
- listByLevel(aiPersonId) → {L1: [...], L2: [...], ...}
- listAvailableForLayer(aiPersonId, levelId) → Array
- get(aiPersonId, summaryId) → Summary | null
- add(aiPersonId, patch) → Promise<Summary | null>
- update(aiPersonId, summaryId, patch) → Promise<Summary | null>
- remove(aiPersonId, summaryId) → Promise<boolean>  // 软删
- setActive(aiPersonId, summaryId, active) → Promise
- setOrder(aiPersonId, summaryIdsInOrder[]) → Promise

【生成层】
- generateLevelSummary(aiPersonId, levelId, opts) → Promise<{ok, error?, summary?, consumedIds?}>
  opts: { generateSummary?: async (lowerSummaries, info) => {ok, summary, title}, force?: boolean }
- buildPlaceholderFromLowerLevel(lowerSummaries, opts) → {title, content, messageCount, dateRange}

【工具】
- buildMemoryContext(aiPersonId) → string  // 给 prompt-builder 注入用
- DEFAULT_LEVELS  // 暴露给 UI 用

八、prompt-builder 集成
================================================================================

位置: js/apps/chat-app/services/prompt-builder.js

build() 末尾在 replyFormatBlock 之后插入:
```js
let memoryContext = '';
try {
    if (opts.memoryInject?.enabled !== false && sdk.memorySummaries?.buildMemoryContext) {
        memoryContext = sdk.memorySummaries.buildMemoryContext(aiPersonId) || '';
    }
} catch (err) {
    console.warn('[prompt-builder] buildMemoryContext failed', err);
}
if (memoryContext) parts.push(memoryContext);
```

buildMemoryContext 输出格式:
```
# 分级记忆(用户启用)

## 年概要(共 N 条)

### 1. 标题 日期范围
概要内容

## 月概要(共 N 条)
...

## 周概要(共 N 条)
...

## 日概要(共 N 条)
...
```

特性:
- 按层级从大到小(L4 → L3 → L2 → L1)排列
- 每层内按 generatedAt 降序
- 只包含 asPrompt.active !== false 的概要
- 没有任何 active 概要时返回空字符串

十一、踩坑记录(重要)
================================================================================

1. ★ 修改变量名 - 不要重复声明 const
   - 早期 patch 用了两次 `const upper / lower`,导致浏览器抛
     `Identifier 'lower' has already been declared`
   - 已修复: 合并为 `const upperLevel = prevLevel; const lowerLevel = nextLevel;`

2. ★ v-html 里禁止用 addEventListener / appendChild
   - 业务 DOM 操作只走 data-app-action 派发(framework 顶层 click 委托)
   - 例外: modal 弹窗(挂到 document.body 上,framework 外)可以用 addEventListener

3. ★ async renderMode detail 重画走二段式
   - 不用 window.__detailRenderTick.value++(会被缓存拦截 + 死循环)
   - 用 window.__appRendererBridge.syncNow({ force: true })

4. ★ 数据持久化
   - 业务 state 不持久化,必须显式写 localStorage / IndexedDB
   - 例: textarea 内容走 localStorage
        memorySummaries 走 aiPerson.socialProfiles.chat 顶层字段(自动 IndexedDB 落盘)

5. ★ cycle 校验
   - 改/增/删 周期必须满足「上层周期 > 下层周期」硬约束
   - 校验失败时 SDK 返回 {ok: false, error: "..."},method 弹灵动岛警告
