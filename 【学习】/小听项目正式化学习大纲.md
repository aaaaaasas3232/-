# 小听项目正式化学习大纲

> 目标：把你现在的“小听启动”从能跑的交互原型，逐步升级成一个可长期维护的正式前端项目。
> 
> 适合对象：已经会一点 HTML / CSS / JavaScript，但不会系统工程化、不熟悉 Vue 项目结构的人。
> 
> 学习方式：**先理解 → 再模仿 → 再改你自己的项目**。

---

## 一、你这次学习的总目标

这次不是为了把所有前端知识都学完，而是为了学会下面这几件最重要的事：

1. 看懂一个 Vue 项目是怎么组织的
2. 学会把一个大文件拆成多个小模块
3. 学会区分“页面结构、交互逻辑、状态、数据、样式”
4. 学会把 demo 项目改造成正式项目
5. 后续你能继续自己维护“小听”

---

## 二、学习完成后的能力标准

如果你学完这个大纲，至少要达到下面这些标准：

- 你知道为什么 `core.js` 不应该越来越大
- 你知道为什么 `index.html` 不能长期承担整个应用页面
- 你知道什么是组件，什么时候该拆组件
- 你知道什么是状态，什么时候该抽状态
- 你能看懂 `src/components`、`src/stores`、`src/composables` 这些目录的作用
- 你能自己新增一个简单 app 页面
- 你能自己继续做结构优化，而不是一直往一个文件里堆代码

---

## 三、先建立正确认知

### 1. 你现在这个项目是什么阶段

你现在的“小听启动”已经不是初级静态网页了。

它已经有：

- 桌面图标
- 灵动岛
- 应用壳层
- 卡片模式
- 手势交互
- 本地数据库雏形

所以它已经是一个**前端交互原型项目**。

但是它还不是“正式项目”，因为它还存在这些特点：

- 逻辑集中在大文件里
- 页面没有真正组件化
- 依赖通过 CDN 引入
- 全局变量较多
- 数据层和视图层耦合偏高
- 缺少规范化目录和工程工具

### 2. 这次学习真正要学什么

你真正要学的不是“再写更多功能”，而是：

- 怎么拆
- 怎么整理
- 怎么归类
- 怎么让半年后的你也能看懂今天的代码

这就是“工程化”的核心。

## 第二阶段：学习 Vue 组件化（建议 2 小时）

### 学习目标

学会把一个大页面拆成多个小组件。

### 你必须理解的概念

#### 1. 什么是组件

组件就是“一个独立的小功能块”。

例如你这个项目里：

- 状态栏可以是一个组件
- 灵动岛可以是一个组件
- 桌面图标区可以是一个组件
- 应用窗口可以是一个组件
- 弹窗可以是一个组件

#### 2. 为什么要拆组件

因为不拆的话：

- 模板越来越长
- 一个 bug 会影响全局
- 你改一个区域时容易碰坏别的区域
- 后续根本没法协作

#### 3. 怎么判断该不该拆

如果某一块同时满足下面 2 条以上，就可以拆：

- 视觉上是独立区域
- 功能上是独立区域
- 内部有自己的交互
- 未来会复用
- 代码超过几十行并且越来越长

### 你这个项目最先该拆的组件

第一批建议拆成：

1. `StatusBar`
2. `DynamicIsland`
3. `DesktopGrid`
4. `AppWindow`
5. `AppModal`

### 本阶段练习

你自己先尝试回答：

- 哪一段 HTML 属于状态栏？
- 哪一段 HTML 属于灵动岛？
- 哪一段 HTML 属于桌面？
- 哪一段 HTML 属于应用窗口？

只要你能在 `index.html` 里把它们圈出来，你就已经进入组件化思维了。

## 第三阶段：学习“状态”是什么（建议 1.5 小时）

### 学习目标

学会区分：

- 哪些是页面数据
- 哪些是交互状态
- 哪些是临时变量

### 你必须理解的概念

#### 1. 状态不是普通变量

比如：

- 当前打开的是哪个 app
- 当前是不是编辑模式
- 灵动岛现在是什么模式
- 当前详情页打开了没有
- 卡片模式是不是激活了

这些都属于“状态”。

因为它们一变，界面就会跟着变。

#### 2. 为什么状态重要

如果状态乱放：

- 你自己都找不到从哪改
- 页面为什么变化会说不清
- Bug 会越来越难查

### 你这个项目里的典型状态

你可以重点理解这些：

- `activeAppId`
- `activeRootPageId`
- `detailPageStack`
- `appViewMode`
- `isEditMode`
- `draggingIconId`
- `islandMode`
- `islandSize`
- `appModal`

### 本阶段练习

请你自己分类：

#### 页面状态
- 当前打开应用
- 当前页面
- 当前详情页

#### 桌面状态
- 是否编辑模式
- 当前拖拽图标

#### 灵动岛状态
- 当前模式
- 当前大小
- 当前内容

#### 弹窗状态
- 是否显示
- 类型
- 文案

只要你能把它们分类，后面学 `Pinia` 才不会懵。

## 第四阶段：学习 composable，拆 `core.js`（建议 2 小时）

### 学习目标

理解为什么大逻辑文件要拆成多个功能模块。

### 你必须理解的概念

在 Vue 3 里，很多逻辑会写成 `useXxx()`。

比如：

- `useDynamicIsland()`
- `useDesktopEdit()`
- `useCardMode()`
- `useAppNavigation()`

这种写法的意义是：

- 把一类逻辑包在一起
- 方便复用
- 方便单独修改
- 方便查 bug

### 你这个项目已经有雏形

其实你现在的 `core.js` 已经有了 composable 的味道。

这说明你不是从零开始，而是已经走到半路了。你现在要做的，不是重学，而是**把半成品整理成规范形式**。

### 你后续要学会的拆法

把 `core.js` 拆成类似下面这样：

- `useSystemClock.js`
- `useDynamicIsland.js`
- `useAppNavigation.js`
- `useDesktopEdit.js`
- `useCardMode.js`

### 本阶段练习

请你尝试回答：

1. 哪些函数属于“灵动岛逻辑”？
2. 哪些函数属于“桌面编辑逻辑”？
3. 哪些函数属于“卡片拖拽逻辑”？
4. 哪些函数属于“导航逻辑”？

只要你能分组，说明你已经开始会拆了。

---

## 第五阶段：学习正式项目目录结构（建议 1 小时）

### 学习目标

学会看懂正式 Vue 项目为什么会有很多目录。

### 推荐目录结构

```text
src/
  components/
    system/
    desktop/
    app-shell/
  composables/
  stores/
  services/
  apps/
  styles/
  types/
  App.vue
  main.js
```

### 每个目录的作用

- `components/`：放页面组件
- `composables/`：放逻辑复用函数
- `stores/`：放全局状态
- `services/`：放数据库、本地存储、接口调用
- `apps/`：放每个 app 的配置和页面内容
- `styles/`：放全局样式和变量
- `types/`：放类型定义（以后学 TypeScript 时更重要）

### 本阶段练习

请你自己给“小听”设想一个目录：

- 哪些内容该进 `components`
- 哪些内容该进 `services`
- 哪些内容该进 `apps`

## 第六阶段：学习工程化工具（建议 1 小时）

### 学习目标

知道正式项目为什么不用 CDN，而要用构建工具。

### 你必须理解的概念

#### 1. 为什么不用 CDN 方式长期开发

因为 CDN 虽然方便，但它的问题是：

- 不方便模块化
- 不方便拆文件
- 不方便版本管理
- 不方便多人协作
- 不方便打包优化

#### 2. 为什么要用 Vite

`Vite` 是 Vue 项目很常见的开发工具，它能帮你：

- 启动本地开发环境
- 支持模块导入导出
- 自动刷新页面
- 支持构建正式产物
- 配合 ESLint / Prettier 做规范化开发

### 你后续要接触的工具

- `Vite`
- `npm`
- `ESLint`
- `Prettier`
- `Pinia`

这几个不用一次全精通，但你要知道它们分别干什么。

## 第七阶段：第一次把“小听”迁移成正式结构（建议 1~2 小时）

### 学习目标

完成一次最小迁移。

### 最小迁移目标

只做这些，不要贪多：

1. 创建一个 `Vue + Vite` 项目
2. 把原来的主界面搬进 `App.vue`
3. 把 `main.css` 接进去
4. 把 `apps.js`、`db.js`、`core.js` 先迁进去
5. 先保证页面继续能跑

### 注意

这一阶段不是为了“拆得完美”，而是为了：

- 先进入正式项目环境
- 先学会怎么运行
- 先学会怎么组织文件

### 本阶段练习

迁移成功以后，你要能回答：

- `main.js` 是做什么的？
- `App.vue` 是做什么的？
- 为什么现在可以 `import` 文件了？
- 为什么现在不需要在 HTML 里手动写多个 `<script>`？

## 第八阶段：开始真正重构（持续进行）

### 学习目标

在正式项目里继续把结构变干净。

### 重构顺序建议

#### 第 1 步：拆组件
先拆：

- `StatusBar`
- `DynamicIsland`
- `DesktopGrid`
- `AppWindow`
- `AppModal`

#### 第 2 步：拆 composables
再拆：

- `useDynamicIsland`
- `useAppNavigation`
- `useDesktopEdit`
- `useCardMode`

#### 第 3 步：抽 service
再整理：

- `db.js` → `services/storage.js`
- `apps.js` → `apps/registry.js`

#### 第 4 步：引入状态管理
最后再考虑：

- `Pinia`
- 全局状态统一管理

### 注意

不要一上来就追求高级。

先保证：

- 页面还跑得起来
- 每拆一步你都知道自己在干什么
- 拆完更容易理解，而不是更乱

---

## 五、你后续每次学习都要问自己的问题

每次改代码前，先问自己：

1. 我现在改的是结构、样式、状态，还是数据？
2. 这段代码属于哪个模块？
3. 它以后会不会继续长大？
4. 如果会长大，现在是不是就该拆？
5. 我是在“继续堆功能”，还是在“让项目更清楚”？

这五个问题很重要。

---

## 六、学习时最容易踩的坑

### 坑 1：一上来就想全重写

不要这样。你应该：

- 先迁移
- 再拆分
- 再优化

### 坑 2：一边学一边乱加功能

如果你现在目标是“正式化”，就先别疯狂加新玩法。

先把结构理顺。

### 坑 3：只抄代码，不理解职责

你以后真正能独立维护项目，不是因为你背了代码，而是因为你知道：

- 为什么这个东西放这里
- 为什么这个状态不该放那里
- 为什么这块要拆组件

### 坑 4：一看到新词就怕

你后面会看到很多词：

- 组件
- composable
- store
- service
- props
- emit
- Vite
- Pinia

别怕。它们本质上都只是在回答一个问题：

**“这段代码应该放哪？”**
