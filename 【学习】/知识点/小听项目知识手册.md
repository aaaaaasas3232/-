## 1.1 · `data-app-action` 机制（按钮任务传递）

### 它是什么

给按钮绑定“点击后要做什么”的信息。

### 在哪里

- **写任务单**：`js/apps.js` 的 `serializeAction` + `renderActionButton`
- **读任务单**：`js/core.js` 的 `handleAppContentClick`

### 流程图

```
apps.js（写任务单）→ 按钮的 data-app-action 属性
                        ↓ 用户点击
core.js（读任务单）→ handlePageAction
                        ↓
                    执行动作：
                    · detail   → 进详情页
                    · modal    → 开弹窗
                    · switchPage → 切页面
                    · appMethod  → 调 app 方法
```

### apps.js 端（写）

```js
function serializeAction(action) {
    return escapeHtml(JSON.stringify(action || {}));
}

function renderActionButton(action) {
    return `
        <button class="detail-link" data-app-action='${serializeAction(action)}'>
            <span>${escapeHtml(action?.label || '查看')}</span>
            <span>›</span>
        </button>
    `;
}
```

### core.js 端（读）

```js
function handleAppContentClick(event) {
    const actionElement = event.target.closest('[data-app-action]');
    if (!actionElement) return;
    handlePageAction(actionElement.dataset.appAction);
}
```

### 举例

```js
// 生成一个“进详情页”的按钮
renderActionButton({ action: 'detail', pageId: '123', label: '查看详情' })
// → <button data-app-action='{"action":"detail","pageId":"123"}'>
```

### 一句话总结

> `apps.js` 负责把动作写成字符串贴到按钮上，`core.js` 负责读出来执行。

## 1.2 · 数据驱动 UI（声明式渲染）

### 它是什么

把“写死的内容”变成“用数据生成”。

### 对比

| 写法 | 描述 |
|------|------|
| 老式硬写 | 每个按钮单独写 HTML，100个按钮复制100次 |
| 数据驱动 | 一个模板 + 不同数据，要多少生成多少 |

### 好处

1. **更易维护**：样式只改一处，全局生效
2. **更易扩展**：加新按钮类型，只改数据，不改模板
3. **更安全**：`escapeHtml` 防止 XSS，写死了就没有保护
4. **更灵活**：根据不同情况动态生成不同按钮

### 一句话总结

> 先定义好结构，数据往里一套，页面就出来了。

## 1.3 · `normalizeTextList`（统一成干净数组）

### 它是什么

把“可能是数组、可能是单值、可能是空值”的输入，统一整理成一个干净数组。

### 原代码

```js
const normalizeTextList = value =>
    Array.isArray(value) ? value.filter(Boolean) : value == null || value === '' ? [] : [value];
```

### 逻辑拆解

```
输入是什么？
    ↓
是数组吗？
    ├─ 是 → value.filter(Boolean)   → 把里面的空项清掉
    └─ 否 → 是空值吗？
              ├─ 是（null/undefined/''）→ []         → 空数组
              └─ 否 → [value]           → 包成数组
```

### 例子

```js
normalizeTextList(['a', '', null, 'b'])  // ['a', 'b']
normalizeTextList('a')                    // ['a']
normalizeTextList('')                    // []
normalizeTextList(null)                  // []
normalizeTextList(undefined)             // []
```

### `filter(Boolean)` 是什么意思

把数组里“假值”过滤掉。

假值包括：`''`、`null`、`undefined`、`0`、`false`、`NaN`

```js
['a', '', null, 'b'].filter(Boolean)
// 等价于：
['a', '', null, 'b'].filter(item => Boolean(item))
// 结果：['a', 'b']
```

### `value == null` 是什么意思

这是 JS 里一个常见简写，等价于：

```js
value === null || value === undefined
```

专门同时判断 `null` 和 `undefined`，但不会把 `''`、`0`、`false` 算进去。

### 一句话总结

> 任何输入都尽量整理成干净的数组，不留空项。

## 1.4 · XSS 防护（escapeHtml）

### 什么是 XSS

- 全称：`Cross-Site Scripting`（跨站脚本攻击）
- 本质：攻击者把恶意 JS/HTML 注入到页面中，在受害者浏览器里执行
- 常见后果：偷 cookie、冒充用户操作、篡改页面内容、钓鱼

### escapeHtml 原理

将特殊字符编码为 HTML 实体：

| 原始字符 | 转义后 | 说明 |
|---------|--------|------|
| `&` | `&amp;` | 防止破坏实体 |
| `<` | `&lt;` | 防止被当成 HTML 标签 |
| `>` | `&gt;` | 防止被当成 HTML 标签 |
| `"` | `&quot;` | 防止属性值被闭合 |
| `'` | `&#39;` | 防止单引号闭合 |

### 示例

用户输入：`<script>alert(1)</script>`
转义后：`&lt;script&gt;alert(1)&lt;/script&gt;`
浏览器显示：原文显示，不会执行脚本。

### 局限性

| 场景 | escapeHtml 够用吗 | 补充措施 |
|------|------------------|----------|
| 插入 HTML 文本节点 | ✅ 够 | |
| 插入 `<a href="...">` | ❌ 不够 | 校验 URL 协议，只允许 `http/https` |
| 插入 `<img src="...">` | ❌ 不够 | 同上，防止 `javascript:` 伪协议 |
| 插入 onClick 等事件 | ❌ 不够 | 绝不能在事件属性中拼接用户输入 |
| 插入 `<style>` | ❌ 不够 | 白名单样式，过滤 `expression`/`javascript:` |
| 插入 JS 字符串 | ❌ 不够 | 需针对 JS 的转义 |

### 一句话总结

> 把用户输入当有害文本转义后再插入，非必要不直接拼接 HTML。

## 1.5 · `serializeAction` + `renderActionButton`

### 是什么

这是“数据驱动 UI”在按钮上的具体实现。

- `serializeAction(action)`：把动作对象转成字符串
- `renderActionButton(action)`：用模板生成按钮 HTML

### 为什么需要两个函数

- `serializeAction` 负责“序列化”（对象 → 字符串），用 `JSON.stringify` + `escapeHtml`
- `renderActionButton` 负责“渲染”（字符串 → 按钮 HTML 片段）

分开写的好处：
- 序列化逻辑可以复用
- 渲染模板可以统一维护
- 数据和视图分离

### 一句话总结

> 把“按钮干什么”和“按钮长什么样”分开管理，数据一变，页面就变。

# 第2部分 · 常见错误记录

---

## 2.1 · 语法错误

### DOCTYPE 大小写写错

- ❌ 错误：`<html Docty>` / `<Doctype html!>`
- ✅ 正确：`<!DOCTYPE html>`

记忆口诀：`!` + `DOCTYPE` + 空格 + `html`（全小写）

### 模板字符串引号用错

- ❌ 错误：`"应用名称${appName}"`
- ✅ 正确：`` `应用名称${appName}` ``

记忆口诀：**变量进字符串，反引号反引号**

### script 标签内代码不缩进

- ❌ 错误：一行堆在一起
- ✅ 正确：缩进 4 个空格

### style 标签里的 CSS 没写内容

- ❌ 错误：`<style></style>` 是空的
- ✅ 正确：里面要有 CSS 规则

---

## 2.2 · Vue 3 错误

### function 不能省略

- ❌ 错误：`getTime() { return 1; }`
- ✅ 正确：`function getTime() { return 1; }`

只有**箭头函数**赋值给变量时，`function` 才能省略。

### Vue.createApp 返回值要赋值

```js
const app = Vue.createApp({...});  // ✅ 必须存起来
Vue.createApp({...}).mount('#app'); // ❌ 没有保存，后面无法调用 mount
```

### Vue.ref() 的 .value

```js
const systemTime = Vue.ref("08:30"); // 创建
systemTime.value = "09:00";          // 修改（必须加 .value）
console.log(systemTime.value);         // 读取（必须加 .value）
```

模板里 `{{systemTime}}` **不用** `.value`，Vue 自动处理。

### setup() 里返回的数据不等于页面直接能用

```js
setup() {
    return { steps: [...], answers: {...} };
}
// 以为这样就一定能用？不一定！
```

记忆口诀：**setup 只是交卷，老师收了才算数**

---

## 2.3 · IndexedDB 错误

### async/await 不是什么时候都要用

- `add()`、`delete()`、`put()`：不需要，够用
- `get()`：返回 request 对象，用 `onsuccess` 回调

只有遇到**嵌套查询**（一个结果依赖另一个）时，`async/await` 才有价值。

### IndexedDB 版本不能降

```js
// ❌ 浏览器已有版本2，降回1会报错
indexedDB.open('listen_db', 1);

// ✅ 不知道当前版本，直接不写版本号
indexedDB.open('listen_db');
```

记忆口诀：**数据库版本只许升，不许降**

### renderPage 里不要混用同步和异步

```js
// ❌ 以为加 async 更高级
async function syncState() {
    return { currentStepIndex: 0 };
}

// renderPage 里直接写：
const state = methods.syncState(); // 这时候拿到的不是对象，是 Promise！
```

记忆口诀：**渲染马上要的数据，别偷偷变异步**

### methods 之间互调，不要假设 this 上一定有同级方法

```js
// ❌ 以为可以直接调
syncState() {
    const state = this.getState(); // 可能报错：this.getState is not a function
}
```

记忆口诀：**别想当然信 this，先看框架怎么绑**

---

## 2.4 · CSS / 布局错误

### Dock 图标不能直接硬缩 CSS

- 桌面图标是 `60x60` 完整结构
- Dock 图标只有 `40x40`
- 有些图标是“高光层 div + SVG”组合，只缩 `svg` 不会缩高光层

记忆口诀：**桌面图标看结构，Dock 图标看缩放容器**

### 绝对定位元素需要参照盒子

```css
/* ❌ 外层没有尺寸，绝对定位图形位置不对 */
.icon-wrapper { }

/* ✅ 外层要给坑位 */
.icon-wrapper {
    width: 100%;
    height: 100%;
}
```

记忆口诀：**绝对定位想站稳，外层盒子要给坑位**

### 遇到显示问题，先看原版怎么做

记忆口诀：**先看原版，再动样式；先懂结构，再改表现**

# 第3部分 · 重要模式

---

## 3.1 · 数据与视图分离

核心思路：

- 数据（state）描述“有什么”
- 模板（render）描述“怎么显示”
- 事件（action）描述“做什么”

好处：改数据不改模板，改模板不改数据，互不干扰。

---

## 3.2 · 事件委托

原理：不在每个按钮上绑事件，而是在父容器上统一监听。

```js
// ❌ 低效：100个按钮绑100个事件
button1.onclick = handle; button2.onclick = handle; // ...

// ✅ 高效：父容器一个事件代理
container.addEventListener('click', (e) => {
    const btn = e.target.closest('[data-app-action]');
    if (btn) handlePageAction(btn.dataset.appAction);
});
```

你的项目 `core.js` 里就是这样做的。

---

## 3.3 · 声明式 vs 命令式

| 风格 | 描述 | 举例 |
|------|------|------|
| 命令式 | 一步一步告诉电脑怎么做 | 创建按钮 → 加 class → 加属性 → 加内容 |
| 声明式 | 只告诉电脑要什么结果 | `renderActionButton({action: 'detail'})` |

现代前端框架（Vue、React）都倾向声明式。

# 第4部分 · 速查表

---

## 遇到 XSS 攻击？

→ 用 `escapeHtml()` 转义后再插入

## 遇到按钮不知道点了干嘛？

→ 找按钮的 `data-app-action`，看里面的 `action` 字段

## 遇到 TypeError: Cannot read properties of undefined？

→ 可能是异步函数当同步用了，检查有没有 `.value` 或 `await` 漏写

## 遇到数据库版本报错？

→ 版本号只能升，不能降；不知道版本就不写版本号

## 遇到绝对定位图形位置跑偏？

→ 检查外层盒子有没有给 `width: 100%; height: 100%`

## 遇到 Dock 图标和桌面图标大小不一致？

→ 桌面看结构，Dock 看缩放容器，不要直接用 CSS 缩 svg
