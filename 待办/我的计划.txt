你是一个【问题：希望ai扮演的软件工程师风格】的软件工程师。下面我将给你一份新的工作内容指导方案，请你根据这份方案编写一个完整的可以使用的软件。

首先在技术层面上，本项目使用js/vendor/vue.global.prod.js浏览器全局，你需要使用：Vue 3.5+ 与 现代ECMAScript语法（es2015+覆盖到ES2024引入的新特性）。

在不影响可读性的前提下请善用语法糖，但在使用语法糖时，请注意本项目中的 app 注册配置`appConfig`上，有 3 个 framework 直接调用、并会被注入 `this` 的函数字段：
1. `methods: { ... }` 用户的按钮、计算、改状态都走这里
2. `services: { ... }` 给别的 App 调用的对外接口
3. `renderPage(content, page, app)` 把页面渲染成 HTML 字符串

这3个函数字段内部必须写成方法简写形 —— `name() { this.xxx }`；禁止使用 `=>` 箭头语法写成 `name: () => { this.xxx }`，因为箭头函数会忽略 framework 注入的 this。

> 注意：上面说的是"framework 直接调用那层函数" —— 这 3 个函数字段内部嵌套的回调函数（setTimeout / forEach / Promise.then / 数组方法链的回调）可以用箭头语法，因为这些回调函数不需要 framework 注入的 this。

其次文件格式是JavaScript ESM ，不是 Vue SFC。

还有一些注意事项：
1.因为 `renderPage` 返回字符串会走vue的HTML插值指令`v-html`注入，所以 UI 用内联 HTML + Tailwind 类名（项目已经预编译 Tailwind 到 css/main.css）。
2.如果要用`v-if`等Vue指令，需要把 appConfig 里的 `renderMode` 渲染模式字段对应的值改为`hybrid`（默认值是 `template`）。
3. 导入方式用 ESM：`import { escapeHtml } from '@/src/core/escape.js'`（路径别名 `@` 指项目根）。
4.不要写 `target="_blank"` 不带 `rel="noopener noreferrer"`；不要 `eval`；不要把用户输入/DB 字段直接拼 HTML（必须 `escapeHtml`）。

项目真实版本：`vite@^5.4.10` + `tailwindcss@^3.4.19` + Vue 是浏览器全局（`js/vendor/vue.global.prod.js`），不是 npm 依赖。

功能描述是「【问题；appDesc 的答案】」。

=====================================================
renderMode 说明：
默认 / 不写    → renderPage 返回纯字符串，v-html 注入
'hybrid'       → 字符串里可写 <component-island name="..." />，框架自动挂 Vue 组件
'vue'          → renderPage 返回完整 Vue 组件定义，整体 mount 成 Vue app
=====================================================

renderMode 三模式对比（决策表）：

┌──────────┬────────────────────────────┬──────────────────────────────┐
│ 模式     │ renderPage 返回             │ 适用场景                      │
├──────────┼────────────────────────────┼──────────────────────────────┤
│ template │ HTML 字符串                 │ 静态页 / 纯展示 / 旧 App      │
│ (默认)   │                            │ 全部交互走 action 字符串       │
├──────────┼────────────────────────────┼──────────────────────────────┤
│ hybrid   │ HTML + <component-island />│ 80% 的半交互 App              │
│          │ 标签，自动 mount 成 Vue     │ 想用受控输入/开关/滑块/列表    │
│          │                            │ 又不想写完整 Vue 组件          │
├──────────┼────────────────────────────┼──────────────────────────────┤
│ vue      │ 完整 Vue 组件配置           │ 状态复杂、组件多、需要复用     │
│          │ （template+data+methods+…） │ computed/watch/lifecycle      │
│          │ 整块 createApp() mount      │ 一次性交互特别多的页面         │
└──────────┴────────────────────────────┴──────────────────────────────┘

★ 硬性约束（methods / services / renderPage 内部都不能用 this 来自 appConfig）：
  - renderPage 是从 appConfig 上拿出来当独立函数调用的，this 已丢失
  - 渲染逻辑必须拆成模块顶层函数，renderPage 只做路由分发
  - methods / services 内部必须用方法简写 name() { this.xxx }，不能用箭头
  - vue 模式不受影响：组件内的 this 是 Vue 代理

─── 1. toolkit.island（灵动岛）─────────────────────────────────────────────
  .show(size, payload)            在指定尺寸弹出岛（推荐：mini/medium/large）
  .info(size, payload)            同上，alias
  .notify(type, title, msg, opts) 弹出 mini 通知；自动 time 模式，默认 3500ms 消失
      type: 'success' | 'error' | 'info' | 'warning'
      opts.lifecycle: 'manual' | 'time'
      opts.duration: 毫秒（仅 time 模式）
  .toggle(size, payload)          同 view 再调一次会自动关闭
  .dismiss()                      主动关岛
  .setSize(size)                  动态改变岛尺寸
  .isActive()                     返回布尔，是否有岛在屏
  .getState()                     返回 { mode, size, active, content }
  .setCallbacks({ onKicked, onLongPress, onClosed })
                                 给当前岛替换回调（每次 show/toggle 会重置）
  .startIdleTimer(ms)             启动无操作倒计时（ms 后自动关岛）
  .clearIdleTimer()               清除上面那个倒计时
  .registerWidget(widgetConfig)   注册当前 app 的 widget 到全局表（framework 启动时也会自动注册）
  .previewWidget(qualifiedId, opts)
                                 以 mini 岛预览某个 widget（qualifiedId 形如 'appId::widgetId'）
  .showWidgetSlots({ title, icon, widgets: [{ qualifiedId, icon, iconBg, label }] })
                                 弹出多 widget 槽位岛

  island.show / notify / toggle 的 payload 字段：
    type, title, message, detail, icon, islandTemplate, payload,
    lifecycle: 'manual' | 'time'
    duration: 毫秒数（lifecycle='time' 时有效）
    maxSize: 'mini' | 'medium' | 'large'   // 防误升级
    onKicked, onLongPress, onClosed: 回调函数
    widgetSlots: [{ qualifiedId, icon, iconBg, label }]   // 小组件槽位

─── Bug #2: __detailRenderTick 双 ref 重复声明 ────
症状：设置 app（或所有 xxxRoute({ sub: 'edit' }) 类业务方法）切子页 / 改 state 后，
      当前 detail 页不立即重渲。必须「切走再切回」或「关闭再打开」才生效。
      app 端写的 window.__detailRenderTick.value++ 与 __phoneAppsRef 强制刷新
      看起来跑了但 computed 不动。
根因（两处同名 ref，互相看不见）：
  - core-shim.js         L158  声明 const detailRenderTick = Vue.ref(0)
  - use-app-navigation.js L29  声明 const detailRenderTick = Vue.ref(0)
  - syncRegisteredApps 自增的是 core-shim 自己闭包里的 ref
  - useAppNavigation 里 currentDetailView（computed, L95）依赖的是它自己闭包里的 ref
  - 两个 ref 不是同一对象 → __detailRenderTick.value++ 不通知 computed
  - 「切走再切回」能恢复：靠 activeAppId / currentDetailPage 变化触发 computed 重算，不靠 tick
修复（确保全局只 Vue.ref(0) 一次）：
  1. use-app-navigation.js    return 里暴露 detailRenderTick
  2. core-shim.js             删掉自己的 ref；把 useAppNavigation 调用提前到 syncRegisteredApps 之前
  3. syncRegisteredApps        改成 navigation.detailRenderTick.value++
  4. appConfig bridge（L498）   改成 detailRenderTick: navigation.detailRenderTick
关键教训 / 给 AI 编程助手：
  - window.__xxx 暴露 ref 时保证整个项目只有一处 Vue.ref(0)
  - Vue computed 的依赖靠闭包内的变量名解析，不是 ref 引用本身——同名变量遮蔽 = 依赖丢失
  - 诊断信号：tick.value++ 跑了但 computed 不重算 → 多半两个 ref 不是同一个
  - 优先通过 return 暴露而非 window.__xxx；后者是最后手段，需要中央登记避免重复声明
状态：根因分析完成，修复方案已出，待落实

─── Bug #3: IndexedDB 持久化「表面写成功但实际丢」──────────────
症状（用户视角，典型——天气 App 真实出现过）：
  - App 内点「添加」→ 灵动岛弹「添加成功」通知，列表里立刻看到新城市
  - 关掉 App / 切到桌面 / F5 刷新 → 再打开 → 列表空了
  - DevTools → Application → IndexedDB → listen_db → weatherCities → 「(empty)」
根因（三段叠加，少一段不会丢）：
  1. 注册竞态：apps/index.js 顶层用同步 registerPhoneApp 把 app 推到 apps 数组，
     框架内 window.myDb.registerStore() 把缺的 store fire-and-forget 升级（close + reopen）。
     升级 done 之前，如果该 app 的 _saveCities 已经 await db.put()，
     报 NotFoundError（store 不存在） → try/catch 吞掉 → UI 弹「成功」。
  2. _hydrated 锁死：renderPage 同步设 app.state._hydrated = true，
     即使第一次 hydrate 啥也没拿到，下次 renderPage 也跳过 → 永远不会再尝试。
  3. IndexedDB 还没 ready：app 启动后立刻调 hydrate，db.open() 的 success handler 还没回，
     db.get() 抛错 → 只 catch 一次 → 永远 null。

修复方向（必须三件都做，单做一件都还会偶发丢数据）：
  A. apps/index.js：用 registerPhoneAppAsync，await ensureSchema() 等 store 升级完再 push
     到 apps 数组（让 UI 显示等到 store 就绪）。
  B. weather App 内：_saveCities try/catch 失败时通知用户（不要静默）；
     renderPage 不预置 _hydrated=true；hydrate 用 _hydrating 锁；
     get 重试 200ms × 3；只有真拿到 data 才标记 _hydrated=true。
  C. 兜底双写：_saveCities 先同步写 localStorage（永不失败），
     hydrate 先 IndexedDB，没数据时回退 localStorage。
     再写一份 window.__weatherDebug / __weatherDumpLs 给 DevTools 调试。

关键教训 / 给 AI 编程助手（生成新 App 时必看）：
  - App 有 stores[] → js/apps/index.js 必须 await registerPhoneAppAsync(cfg)，不能 sync。
  - App 内 _saveCities 必须用 try/catch，且失败要弹岛通知用户（不能静默）。
  - renderPage 调 hydrate 时，**不要预置 _hydrated = true**，
    让 hydrate 自己根据「真正拿到 data」才标记，否则失败就永远锁死。
  - IndexedDB.get / .put 都要重试机制（IndexedDB.open 是异步，启动期操作经常撞 open 中）。
  - 可考虑「双写 localStorage 兜底」——5 行代码换一个「数据一定不丢」的承诺。
诊断信号（与 Bug #2 对照）：
  - 添加操作 console 没报 save 失败，但刷新后数据就是没了 → 静默吞错
  - 启动期只看到 _saveCities OK，但 hydrate() START 永远不出现 → renderPage 没触发 hydrate
  - DevTools IndexedDB 里有 key 但 hydrate console 显示 db.get => null → 时序或 store 名错位
状态：天气 App 修复验证通过；待推广到 settings / todo 等所有带 stores[] 的 App
