# 顶栏视觉断层（Status bar / Nav bar discontinuity）

> 写于 2026-08-02 修复 weather-app 详情页"三张渐变拼接"问题后。
> 配套文件：`待办/框架顶栏视觉断层问题.md`（问题档案）、本文件（已修复 + 通用解法）。

---

## 0. 一句话

iOS HIG 要求 **状态栏（status bar）+ 导航栏（nav bar）+ 背景** 视觉一体。
**永远不要让业务层在 detail / page 上自己画背景**——背景应该只由框架层 `.app-background-layer` 一张铺满，业务内容是「半透白毛玻璃卡」漂浮在背景上。

---

## 2. 这次出问题的样子

weather-app 详情页打开北京：

```
┌──────────────┐  ← 状态栏（z-index 999，默认黑字 #000） 独立的颜色
│  9:41   📶 5G│
├──────────────┤  ← 视觉断层！这里能看到色界
│  ←  北京    │  ← .app-detail-header 一开始是 rgba(255,255,255,0.86) 白色磨砂
├──────────────┤
│  17°  多云   │  ← .wth-detail-head 自己画了一张深色渐变（业务层）
│              │
│ ──小时预报── │  ← 0.1 透明白卡片
│ ──7天预报── │  ← 0.1 透明白卡片
│              │
│  湿度  风速  │  ← 0.1 透明白卡片
└──────────────┘
```

**眼睛看到的"三张渐变"**：
1. 顶部 `.app-detail-header` **白色磨砂**
2. 中间 `.wth-detail-head` 业务层自己画的 `getWeatherGradient(condition)` 渐变
3. 卡片之间透出的 `.app-background-layer` 框架层渐变

**根因**：业务层（`.wth-detail-page`）渲染时 inline `style="background: 渐变"` —— 覆盖了框架层的 `.app-background-layer`，导致**三层不同来源的背景**叠在一起。

## 3. 修复架构（方案 C：CSS 变量驱动）

### 3.1 框架层（永远只此一张背景）

`.app-background-layer` 是 `.app-shell` 内**第一个**子元素，`position: absolute; inset: 0;`，被 `.app-shell`（`overflow: hidden; border-radius: 40px`）裁剪成屏幕圆角矩形。

它的 background 来自 `activeAppBackgroundStyle`：

```js
// js/framework/use-app-navigation.js
const activeAppBackgroundStyle = Vue.computed(() => {
    const app = activeApp.value;
    if (!app) return { background: 'linear-gradient(180deg, #f8fafc 0%, #ffffff 100%)' };
    let bg = null;
    if (typeof app.getBackground === 'function') {
        try { bg = app.getBackground(app.state); } catch (_) {}
    }
    return { background: bg || app.background || app.color || 'linear-gradient(...)' };
});
```

**App 在 detail-page 切换不同城市时**，mutate 一个 ref 后 `++window.__detailRenderTick.value`，让这个 computed 自动重算。

### 3.2 状态栏颜色（v0.29 新增）

```js
const currentStatusBarColor = Vue.computed(() => {
    const app = activeApp.value;
    if (!app) return '#111827';
    if (app.statusBarColor) return app.statusBarColor;
    const topbar = activeAppTopbar.value;
    if (topbar?.color) return topbar.color;
    // ★ App 暴露了 getBackground（动态背景）→ 默认白字
    if (typeof app.getBackground === 'function') return '#ffffff';
    return '#111827';
});
```

**优先级**：app 指定 > topbar 颜色 > getBackground 触发（全屏背景）默认白 > 兜底黑。

### 3.3 状态栏不再写死

`css/main.css`：

```css
.statusBarContainer {
    /* v0.29：颜色由 framework inline 注入，不要写死 */
    color: inherit;
}
.statusBarRight {
    color: inherit;
}
```

`statusBarLeft` / `statusBarRight` 内部子元素（时间、信号、5G、电量）已经在模板里用 `:style="{ color: currentXxxColor }"`，本来就跟随。

### 3.4 业务层：绝不画背景

`js/apps/weather-app.js`：

```js
// 修复前
return `<div class="weather-app wth-detail-page" style="background:${getWeatherGradient(weather.condition)};">...`;

// 修复后
return `<div class="weather-app wth-detail-page">...`;
```

`css/weather-app.css`：

```css
.app-detail-page[data-app-id="weather-app"] .wth-detail-page,
.weather-app[data-app-id="weather-app"] .wth-detail-page {
    background: transparent;
    padding: 0 0 24px;
    color: var(--wth-text);
}

/* Hero 文字白（统一渐变背景下） */
.wth-detail-head { color: #ffffff; }
.wth-detail-city { color: #ffffff; }
.wth-detail-big-temp { color: #ffffff; }
.wth-detail-desc { color: #ffffff; }

/* 卡片半透白（0.18，比之前的 0.1 明显） */
.wth-hourly { background: rgba(255, 255, 255, 0.18); }
.wth-forecast { background: rgba(255, 255, 255, 0.18); }
.wth-detail-cell { background: rgba(255, 255, 255, 0.18); }
.wth-detail-grid { /* divider 改白色 */ }
.wth-forecast-row + .wth-forecast-row { border-top: 1px solid rgba(255,255,255,0.18); }
.wth-forecast-track { background: rgba(255,255,255,0.3); }
```

### 3.5 detail header 透明（已在 v0.28）

```css
.app-detail-page[data-app-id="weather-app"] .app-detail-header {
    background: transparent;
    border-bottom: 0;
    backdrop-filter: none;
    color: #ffffff;
}
.app-detail-page[data-app-id="weather-app"] .app-detail-title,
.app-detail-page[data-app-id="weather-app"] .app-detail-subtitle {
    color: #ffffff;
}
.app-detail-page[data-app-id="weather-app"] .detail-back-button {
    color: #ffffff;
}
```

## 5. 通用自检清单（下次访问类似问题先用这 5 步）

### 5.1 视觉断层检查

打开 Chrome DevTools → `Elements` → 选中 App 屏幕区域 → 看 `background` 是从哪一层来的：

```
.app-window
  .app-shell               ← 框架祖先（overflow:hidden, border-radius:40px）
    .app-background-layer  ← ★ 框架层 ★ 唯一允许画整张背景的层
    .app-chrome            ← 业务容器
      .app-topbar
      .app-content
        .app-page-stack
          .app-detail-page ← 业务层，应该是 transparent
            .wth-detail-page
              .wth-detail-head ← 业务层，应该是 transparent
```

**只允许 `.app-background-layer` 画背景**。其它任何层 background 不能是 `渐变/实色`。

### 5.2 状态栏和 nav bar 拼接处

把鼠标放到状态栏底部 1px 边界。如果能看到颜色突然跳变：
- 状态栏用的是 `currentStatusBarColor`（黑），但 nav 是彩色背景 → 状态栏没拿到 topbar.color → 检查 `topbar.color` 设置
- 状态栏是白，nav 透明下面是白墙纸 → App 没暴露 `getBackground` → 加上 `getBackground(state)` 钩子

### 5.3 颜色断层在哪儿

- **深层 pointer events**：在元素上右键 → 检查器 → 看 `background` 计算值
- 整张连续渐变应该是同一张 image —— 在 DevTools 里看多个 div 的 `background-image` 来源
- 业务 div 上若 `style="background: ..."` inline → **删掉**，让框架层接管

### 5.4 卡片文字看不清

详情页统一渐变后，卡片（半透白）上的文字应该是**白**或**深色**。
- 白底 + 白字 → 死路，调卡片 bg 或文字色
- 经验：背景是蓝/紫渐变时，卡片用 `rgba(255,255,255,0.18)` + 文字白

### 5.5 性能/响应式

如果新 App 在 detail-page 切换条件会改背景（比如天气切城市），用 `getBackground(state)` 钩子，并在切换时 `window.__detailRenderTick.value++` 强制重算。

## 6. 通用修复模板

### 6.1 App 想全屏背景 detail 页

```js
// 1. 暴露 getBackground
export default function createMyApp() {
    return {
        id: 'my-app',
        getBackground(state) {
            // 返回 CSS background 字符串
            return 'linear-gradient(180deg, #1a1a2e 0%, #16213e 100%)';
        },
        renderDetailPage(content, page, app) {
            // 2. 不要在业务 div 上画 background
            return `<div class="my-app my-detail">${renderContent(...)}</div>`;
        },
    };
}
```

```css
/* 3. CSS：业务层 transparent + 卡片半透白 */
.app-detail-page[data-app-id="my-app"] .my-detail { background: transparent; }
.my-detail-card { background: rgba(255,255,255,0.18); color: #fff; }
```

框架层 `.app-background-layer` 会自动铺 `getBackground` 返回的渐变；状态栏会自动白字。

### 6.2 App 不想全屏背景（标准 iOS 白）

什么都不做。框架层默认铺 `linear-gradient(180deg, #f8fafc 0%, #ffffff 100%)`（极淡白），状态栏默认黑字，nav 白色磨砂。

### 6.3 App 想自定义 nav 颜色

```js
topbar: {
    bg: 'rgba(255,255,255,0.86)',
    color: '#0f172a',
    titleColor: '#0f172a',
}
```

`topbar.color` 会自动同步到状态栏。

### 6.4 App 想让状态栏变色但 nav 留白

```js
{
    statusBarColor: '#ffffff', // 单独覆盖状态栏
    // topbar 留空 → 默认白磨砂
}
```

## 7. 不要做的事

| ❌ 不要 | 原因 |
|---|---|
| 在 `renderDetailPage` 返回的 div 上 inline `style="background:..."` | 覆盖 `.app-background-layer`，三张渐变 |
| 在 `.app-detail-page` / `.app-page` 上设 background | 同样覆盖 |
| 业务层 div 写 `background: linear-gradient(...)` | 再次叠背景 |
| 状态栏用 `color: #000` 写死 | 框架 `currentStatusBarColor` 失效 |
| nav bar 写 `background: white` + 状态栏默认黑 | 视觉断层 |
| 卡片 background 用 0.05 透明白 | 太淡看不清 |
| 卡片 background 用完全不透明白 | 失去"漂浮"感，跟整张背景割裂 |

## 10. v0.30 回归:全屏背景(2026-08-04)

### 10.1 现象
v0.29 重做后,在 detail 页**业务层 inline 渐变**重新制造了"三张渐变拼接"——
1. `.app-detail-header` v0.29 设了 `rgba(255,255,255,0.18)` + `backdrop-filter` 半透白
2. `.wth-detail-page` inline 当前城市对应天气的渐变
3. `.app-background-layer` framework 也铺一张

视觉上 header 像"漂浮磨砂条"+ 内容渐变 + 框架渐变,断层复现。

### 10.2 根因
v0.29 当时的两个补救理由("主页 .app-page 在 detail-active 时透出来"、"渐变切换断层")**被 v0.28 的 `_detailRenderTick.value++` 触发机制治掉了**:
- `getBackground(state)` 直接读 `state.detailCity`,`openCityDetail` 切城市时 ++tick 强制 computed 重算,单帧切换。
- 主页 .app-page 的 `page-hidden` 由 `currentDetailPage` 驱动,framework template 已暴露。

业务层再画渐变**完全没必要**,反而引入"三层背景"风险。

### 10.3 修复
按 §3.4 / §6.1 方案 C 全屏背景回归:
- `js/apps/weather-app.js` L319 `renderCityDetailPage` —— 删 `style="background:${detailBg};min-height:100%;"`,业务层 transparent。
- `css/weather-app.css` L433 —— `.app-detail-header` 改为 `background: transparent; backdrop-filter: none;`(保留 1px 白色半透 border-bottom 当分隔)。
- `css/weather-app.css` L451 —— `.wth-detail-page` 改为 `background: transparent;`,删兜底渐变。

### 10.4 验证
- 打开天气 App → 点任意城市卡片 → 进入 detail → 整张屏幕**一张**对应天气的渐变(蓝色/灰/紫,跟 condition)。
- 切换不同 condition 的城市(比如从北京 sunny 切到杭州 rainy)→ `.app-background-layer` 单帧换渐变,无拼接。
- 状态栏白字与 nav 标题/返回按钮白字始终跟随渐变亮度(`currentStatusBarColor` 自动)。
- 主页没有"卡片透出"问题(`page-hidden` 由 framework 驱动)。

### 10.5 教训
**业务层永远不要画整张屏幕的背景**——`getBackground(state)` + `.app-background-layer` 是 framework 提供的唯一通道。任何业务层画 background,无论出于什么"补救"目的,都会制造"三张渐变拼接"或"主页透出"这类问题。**根因修不对,补丁叠补丁,迟早复发**。

## 11. v0.30.1:`.app-detail-surface` 灰底漏洞(2026-08-04)

### 11.1 现象
v0.30 改完后,detail 页主体变成对应天气的渐变(正确),但**最底下 40px 的 `.app-bottom` 区(包含 home indicator)是灰色**。

### 11.2 根因
Framework 的 `.app-detail-surface`(`css/core/50-app-shell.css` L372)默认 `background: #f5f5f7`(iOS detail 页默认灰底)。它是 `.app-background-layer` 的兄弟节点,覆盖在 `.app-background-layer` **之上**,会盖住渐变透出来。即使 `.wth-detail-page` 和 `.app-detail-header` 都 transparent,这个灰底仍在。

`.app-bottom` 在 `.app-detail-page` 之**外**(同属 `.app-chrome`),自身 transparent。视觉上它显示的"灰色"其实是 `.app-detail-surface` 的 `#f5f5f7` 透过 transparent 的 `.app-bottom` 透过来。

### 11.3 修复
只针对 weather-app 让 `.app-detail-surface` transparent,不动 framework 默认(其他 app 仍要灰底):

```css
/* v0.30.1 */
.app-detail-page[data-app-id="weather-app"] .app-detail-surface {
    background: transparent;
}
```

### 11.4 验证
- weather-app detail 页:状态栏 / nav / 内容 / 卡片 / `app-bottom`(含 home indicator)整张屏幕**同一张**对应天气的渐变。
- 切城市:渐变单帧切换,无拼接。
- 其他 app(prompt-survey / settings / chat 等)detail 页:仍显示 iOS 默认 `#f5f5f7` 灰底,行为不变。

### 11.5 教训(续 §10.5)
**全屏背景方案 C 的"透明链"必须打通所有会覆盖 `.app-background-layer` 的兄弟节点**:
- ✅ 业务层 `.wth-detail-page` transparent
- ✅ 框架 `.app-detail-header` transparent(weather-app 下)
- ✅ 框架 `.app-detail-surface` transparent(weather-app 下)
- ❌ 任意一个漏了,都会露出一块"非渐变"的色块

下次要做"全屏背景"风格的 app detail 页,**强制走一遍透明链自检清单**:
1. `.app-background-layer` ← framework 已铺渐变,不动
2. `.app-detail-surface` ← transparent(默认是 `#f5f5f7` 灰底!)
3. `.app-detail-header` ← 看是否要磨砂
4. `.app-detail-body` ← transparent(默认 transparent,通常不用改)
5. 业务层 `<div>` ← transparent
6. `.app-nav` / `.app-bottom` ← transparent(framework 默认就是)
