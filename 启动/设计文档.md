---

## 一、项目概述

**小听**是一个 AI 角色扮演手机模拟器。

核心玩法：用户选择一个"人设面具"，选择一个"世界观"，然后像玩智能手机一样，通过各种 App（聊天、微博、电影等）与 AI 角色互动。

**核心原则：人设隔离一切。** 切换人设 = 整个世界换掉，所有数据完全独立。

---

## 二、技术栈

- 语言：HTML + CSS + JavaScript（原生，无框架）
- 数据库：IndexedDB
- 图标：SVG（存放在 `system.js` 的 `SVG_ICONS` 对象中）
- 样式：CSS 类名统一加 `sys-` 前缀，避免冲突
- 代码结构：每个 App 独立文件，放在 `js/` 文件夹

---

## 三、三层核心实体

```
Persona（人设面具）
├── 我是谁（名字/头像/职业/余额）
├── 我绑定了哪些世界观
└── 我用了哪些 App
    └── 每个 App 的数据
        └── 每个 App 里跟哪些 AI 角色聊过天

World（世界观）
└── 可以被多个人设共享
```

### 4.2 球的菜单数据（软编码）

球的菜单从数据库读取，不是硬编码。

```javascript
// 球的菜单项
ballMenuItems = [
    {
        id: "home",
        label: "主页",
        iconKey: "home",         // SVG_ICONS 里的 key
        action: "openHome",
        importance: "high"        // high / medium / low —— 决定排序
    },
    {
        id: "context",
        label: "上下文",
        iconKey: "brain",
        action: "showContext",
        importance: "high"
    },
    {
        id: "persona",
        label: "人设",
        iconKey: "mask",
        action: "switchPersona",
        importance: "high"
    },
    {
        id: "world",
        label: "世界观",
        iconKey: "globe",
        action: "switchWorld",
        importance: "medium"
    }
];
```

**排序规则：**
1. 先按 `importance` 分组：high 在外圈、medium 在中圈、low 在内圈
2. 同重要性内，按创建时间排序（`createdAt`）

### 4.3 App 提示词注入配置

每个 App 可以独立配置怎么把上下文塞进 Prompt。

#### 维度一：注入位置 + 重要性排序

```javascript
promptInjection: {
    // 置顶部（固定基础信息，high importance）
    top: [
        { type: "world",    importance: "high" },
        { type: "persona",  importance: "high" },
        { type: "user",     importance: "high" },
        { type: "time",     importance: "high" }
    ],

    // 置底部（场景相关信息，按 importance 排序）
    bottom: [
        { type: "memory",         importance: "medium" },
        { type: "chat_summary",    importance: "low" }
    ]
}
```

#### 维度二：内容深度（每个上下文项放多少内容）

```javascript
promptInjectionDepth: {
    world: {
        // 世界观：可选择只放名称、完整描述、或 AI 归纳后的摘要
        mode: "full"      // nameOnly / full / summary
    },
    persona: {
        mode: "full"      // full / compact / none
    },
    memory: {
        mode: "summary"   // full / summary / none
    }
}
```

#### 维度三：其他 App 的数据怎么注入

```javascript
// 比如电影 App 正在运行，可以选择注入微博内容
otherAppsInjection: {
    "blog": {
        enabled: true,
        // 完整注入（所有帖子原文）或归纳注入（AI 总结成一段话）
        mode: "summary"   // full / summary / none
    }
}
```

## 五、球的交互逻辑

```
悬浮球（屏幕边缘，始终可见）
    ↓ 点击
展开圆形菜单（类似苹果 AssistiveTouch）
    ├── 高重要性项（外圈）
    ├── 中重要性项（中圈）
    ├── 低重要性项（内圈）
    ↓ 点击某个菜单项
        打开对应弹窗或跳转 App
```

**球的作用：上下文透视 + 快捷跳转**

- 透视：显示 AI 刚才说了什么、当前人设是什么、当前世界观是什么
- 跳转：点哪个跳到哪个 App 的设置页

## 九、什么是"软编码"

**硬编码**（写在代码里，不能改）：
```javascript
// 球的菜单写死了，只能显示这4个
var ballMenu = ["主页", "设置", "上下文", "切换人设"];
```

**软编码**（数据存在数据库里，可以改）：
```javascript
// 球的菜单从数据库读取，随时可以改
var ballMenu = db.get("ballMenuItems");
// 可以加、删、改菜单项，不用改代码
```

**好处：**
- 以后想加菜单项，不用改代码，直接往数据库加一条
- 用户可以自定义菜单
- 可以在 App 里提供"管理球的菜单"的功能

## 十、开场动画 / 加载封面

> 待细化，以下为初步设计思路

### 现状
目前 `index.html` 中已实现基础的加载封面（`#splash`），位于状态栏层下方（`z-index: 49`），Vue `mounted` 后自动淡出移除。

### 待改进方向
- [ ] 替换为更有品牌感的设计（如 Logo 动画、声波动画等）
- [ ] 考虑首次加载 vs 再次打开的区别（`mounted` 仅首次触发）
- [ ] 可设计多帧逐字出现效果，强化品牌记忆

### 备选风格
1. **Logo 放大淡入** — "小听" 从极小缩放至正常，同时透明度 0→1
2. **声波动画** — 适合音乐类 App，播放图标 + 周围声波扩散（呼应"小听"主题）
3. **滑入动画** — 类似 iOS 启动画面，Logo 从底部滑上
